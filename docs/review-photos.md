# Фото к отзывам

Загрузка предназначена для Насти в /admin → Reviews, как на предоставленном скриншоте. Посетителям не открыт анонимный upload.

- Форматы: JPEG, PNG, WebP, до 10 МБ, одно фото на отзыв.
- Upload/Replace отправляет файл через существующий `uploadStudioImage` в bucket `ana-styling-media`, путь `reviews/<review-id>/<uuid>.<ext>`.
- У отзывов, добавленных вручную, `photoUrl` хранится в `studio_sites.content.reviews` и записывается существующей кнопкой «Обновить» вместе с остальным контентом.
- У отзывов посетителей используется существующая колонка `studio_reviews.photo_url`. Как и Publish/Hide для таких отзывов, фото сохраняется сразу; интерфейс подписывает это поведение. Ответ update проверяется по id и photo_url.
- Нужные права уже предусмотрены `supabase/schema.sql`: загрузка в Storage и UPDATE studio_reviews доступны администраторам. Ограничение `photo_url is null` для INSERT посетителей не мешает последующему UPDATE администратором. Новая миграция/таблица/bucket не нужны.
- Публичный сайт отображает фото только вместе с опубликованным отзывом; ссылка позволяет открыть оригинал. У отзывов без фото пустое место не создаётся.
- Delete photo сохраняет пустое значение/null. Старый объект Storage сохраняется, как при удалении фото услуг: это не удаление общего файла, который может использоваться в другом месте.
- Ошибка upload не заменяет существующее фото на локальный data URL. Для production всегда используется Storage; локальный fallback остаётся только в режиме без Supabase.
