# Фото к отзывам

## Перед публикацией

В SQL Editor **существующего** проекта `mmdrnmbhisufsmpluvwh` выполнить `supabase/review-photo-uploads.sql`. Миграция повторяемая, не удаляет данные и не создаёт таблиц или bucket. Не запускать `reviews-stars-reset.sql`: это старый разрушительный reset, который также отключает вложения. Для другого проекта заменить публичный URL в SQL на его URL.

До применения миграции текущие RLS запрещают публичные фото. Отзыв без фото продолжает работать; при отказе Storage форма показывает ошибку и не создаёт отзыв.

## Сохранение

- Посетитель выбирает JPEG/JPG, PNG или WebP до 10 МиБ. Превью использует временный object URL в памяти браузера, не base64 и не localStorage.
- При Submit генерируется UUID отзыва; существующий `uploadStudioImage` загружает файл в **ana-styling-media**, путь `reviews/<review-id>/<uuid>.<ext>`, `upsert:false`.
- После успешной загрузки URL записывается в **studio_reviews.photo_url** вместе с тем же id и `published:false`. Ошибка upload прерывает вставку отзыва. Ошибка записи отзыва сохраняет поля для повторной попытки; уже загруженный объект может остаться без ссылки (как ранее при замене администратором), его очистка требует админского доступа.
- Политика INSERT отзывов проверяет существование объекта именно в этом проекте и папке данного отзыва, MIME и фактический размер по Storage metadata. Публичная загрузка ограничена папками отзывов и расширениями изображений. Права публичного UPDATE/DELETE не добавляются. Ограничение размера при выборе — клиентское; на INSERT отзыва оно проверяется сервером. Для защиты публичного upload от массовой загрузки в обход формы потребуется отдельная мера rate limiting; глобальные ограничения существующего bucket не менялись, чтобы не затронуть другие разделы.
- `loadSubmittedReviews` преобразует `photo_url` в существующее `Review.photoUrl`. Админские Replace/Delete/Publish работают как прежде. Фотография появляется на сайте только вместе с опубликованным отзывом. Сам bucket уже публичный: URL файла доступен до публикации, если он известен.
- Ручные админские отзывы по-прежнему хранят `photoUrl` в `studio_sites.content.reviews` через Save changes. Посетительские отзывы и их фото — в `studio_reviews`, изменения админки сохраняются сразу.

## Приёмка с реальным доступом

После SQL: отправить отзыв с фото, перезагрузить /admin, увидеть фото, заменить/удалить, опубликовать и проверить /reviews в другом браузере (публичные данные обновляются при загрузке, фокусе и каждые 30 секунд). Затем удалить тестовый отзыв через админку. Проверить вариант без фото и все три формата. Убедиться, что запрещены вставка published:true и подстановка несуществующего/чужого photo_url.
