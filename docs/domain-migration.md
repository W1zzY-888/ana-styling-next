# ANA STYLING: перенос с Wix без потери старых ссылок

Подготовлено 23 сентября 2026. DNS и настройки домена не изменены.
Текущий домен: https://www.anastyling.com/ (проверен по sitemap Wix).
Новый сайт пока: https://w1zzy-888.github.io/ana-styling-next/.

## Что подготовлено в коде

- Favicon ICO (16/32/48/64), PNG (192), Apple icon (180) из монограммы оригинального логотипа.
- Open Graph / Twitter Card: логотип, отдельные title/description и абсолютный URL для каждой страницы.
- Canonical, sitemap.xml, robots.txt; /admin не индексируется.
- GitHub Pages preview помечен noindex, follow, чтобы не конкурировать с основным доменом. Роботам разрешено читать его метаданные для превью ссылок.
- При сборке публичные страницы получают snapshot через существующий Supabase-клиент: тексты доступны в HTML без запуска JavaScript. В браузере остаётся обычное обновление данных из Supabase. После важных изменений контента в админке нужно повторить workflow для обновления статического HTML; обычные посетители получают обновления без пересборки.
- Старые страницы услуг, портфолио и главная RU доступны по прежним путям. Формат со слешем в конце согласован с текущим static export.

## Порядок переключения

1. Сохранить доступ к Wix/DNS, текущим Google Search Console и Analytics, текущие DNS-записи и статистику. Согласовать www как основной адрес или сохранить существующий canonical. Не менять MX/TXT почты при переключении сайта.
2. Закончить карту URL для блога, гайда и магазина. GitHub Pages с `output: export` не поддерживает произвольные серверные 301 в next.config. Для объединённых/перемещённых страниц использовать хостинг или прокси с настоящими 301/308, либо сохранить исходные пути. HTML/JS-переадресацию не считать эквивалентом серверного 301.
3. Настроить и подтвердить custom domain в хостинге. Не отключать Wix до готовности нового хостинга, сертификата HTTPS и проверки всех URL.
4. Для сборки в GitHub Actions установить repository variable `NEXT_PUBLIC_SITE_URL=https://www.anastyling.com/`; `NEXT_PUBLIC_BASE_PATH` оставить пустой/удалить. Workflow подставляет /ana-styling-next только для прежнего preview URL. Supabase URL/key/bucket/studio ID остаются прежними.
5. Перед DNS-переключением проверить собранный HTML: canonical и og:url ведут на custom domain, og:image доступен, robots разрешает индексацию, /admin закрыт метатегом noindex, ссылки и файлы не содержат /ana-styling-next. Проверить EN/RU, /admin, загрузку фото, сохранение и публичное чтение.
6. Переключить только необходимые DNS-записи сайта у текущего DNS-провайдера. Регистрацию домена необязательно переносить из Wix. Обеспечить редирект вторичного hostname (www/non-www) на основной и HTTPS.
7. В существующем Search Console проверить главную, услуги, старые URL и отправить новый sitemap.xml. Если домен тот же, инструмент Change of Address не нужен. Сохранить существующие коды Analytics/Search Console, если они использовались в Wix: они не появляются автоматически при переносе.
8. Следить за индексированием, 404, показами/кликами, HTTPS и доступностью. Сохранить редиректы минимум год. Отключить старый хостинг только после проверки перехода трафика.

## Что можно обещать клиенту

Сохранение домена, содержимого и адресов/корректных редиректов помогает сохранить накопленные сигналы. Смена конструктора не обнуляет SEO автоматически, но позиции не гарантируются и временные колебания возможны. Эти настройки — техническая подготовка, не отдельная кампания продвижения.

Превью Telegram/WhatsApp обновляется по правилам и кешу каждого сервиса; сайт отдаёт OG-теги уже в HTML. Новая картинка может появиться не сразу после изменения.
